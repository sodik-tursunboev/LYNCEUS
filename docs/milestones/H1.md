# H1: harden, cut false alarms, look deeper

**Asked by the owner (2026-11-12):** "fix security issues, false positive rate, and deep analysis, and reduce limitations". This plan takes the items from `docs/KNOWN_LIMITATIONS.md`, `docs/milestones/R1.md` and `docs/FEATURES.md` section 20 that can be built **and verified on this machine**, in the order of what they fix. It needs approval before any code changes (CLAUDE.md, "How to work").

**Decisions (owner, 2026-11-12):** plan approved as written; email false alarms measured on the owner's own Gmail, read-only, connected for real (the owner creates the OAuth client and grants consent); Tranco download, a live re-run of the detonator and a local re-read of Edge and Chrome history (counts only) are allowed; ADR-007 approved: hosts encrypted with DPAPI plus a keyed hash.

**What this milestone cannot do** (each needs the owner, money or a third party): code signing (a certificate), Google's app verification for other users, an independent penetration test, a licence for the repository, commercial terms for the threat feeds, and a dedicated VM for detonation. They stay in KNOWN_LIMITATIONS.

**The study is not touched.** `llm-phishing-study` scores the frozen snapshot `ac2a5af` (tag `lynceus-eval-v1`) and its adapter refuses any other commit. No study data (Nazario, SpamAssassin ham, Enron, rewrites, scores) is used here. Ollama is not used either: the study's rewrite run needs it pinned and undisturbed.

## Part A: security

| | Change | Fixes | Size |
|---|---|---|---|
| A1 | **Separate credentials.** The agent keeps the API token. The console gets its own session token, exchanged once for a one-time code (single use, 60 s) that `--open-console` puts in the address fragment instead of the real token. The actor is taken from the credential, not from the `X-Lynceus-Actor` header: a console session is always `user` and can never act as `policy` or `agent`. | R1 "one token for everything", "token in the URL fragment / browser history" | M |
| A2 | **Audit log append-only for real.** A PostgreSQL trigger refuses UPDATE, DELETE and TRUNCATE on `audit_logs` (new migration). Detonation requests and failed sign-ins (counted per minute, no token text) are audited too. | "append-only by convention only" | S |
| A3 | **RDAP connects to the address it checked.** Reuse `core/urls/safe_fetch.py`'s connect-by-validated-IP, so a registry name that resolves to a private address is refused. | residual SSRF in RDAP | S |
| A4 | **Secrets out of plain `.env`.** API token, provider keys and database password move to a DPAPI-protected file (`ctypes` to `CryptProtectData`, no new dependency); `python -m core.secrets set NAME` reads from standard input. A plaintext `.env` value still works, with a warning. Run `set` from a normal PowerShell: DPAPI keys written from inside the Claude app can land in its private AppData (ADR-024). | "keys are plaintext in `.env`" | M |
| A5 | **Hash-locked Python dependencies** with pip's own `pip lock` (pip 26.2.1, no new tool): `pylock.toml`, and `tasks.py deps` installs with hashes required. | "dependencies lower-bounded, not hash-locked" | S |
| A6 | **A message or file the parser could not finish is no longer silent:** a notification ("not analysed: timeout") and a count in the console. Still UNKNOWN, never safe. | R1 "stored UNKNOWN and nobody is told" | S |
| A7 | **Quarantined files are defanged:** stored DPAPI-encrypted (`ProtectedData` in .NET), so a double-click cannot run them and an antivirus does not react; restore decrypts and checks the SHA-256. Existing quarantined files are converted on first start. | "quarantine folder not encrypted or defanged" | M |
| A8 | **Evidence encryption at rest (ADR-007), if you approve the ADR:** the host column is stored DPAPI-encrypted for display, plus a keyed hash for lookups and grouping. New migration; the console shows hosts as today. | ADR-007 unsigned, hosts in plaintext | M |

## Part C: deeper analysis

| | Change | Fixes | Size |
|---|---|---|---|
| C1 | **CSS hiding through `<style>` blocks:** class, id and tag selectors with `display:none`, `visibility:hidden`, zero size, off-screen, zero opacity or zero font size. Standard library only. | "hiding through a `<style>` block is not seen" | S |
| C2 | **SVG attachments** (a current phishing trick): scripts, event handlers, `foreignObject` forms, `javascript:` and `data:` links, embedded HTML. New rule `file.svg_active`, read in the sandbox with the XML parser already there. | "SVG with scripts" (FEATURES section 20) | S |
| C3 | **Trust only your own provider's `Authentication-Results`:** the topmost header from the receiving server (authserv-id such as `mx.google.com` or Outlook's), not a copy the sender wrote further down. Offline. | "`Authentication-Results` is whatever the header says" | S |
| C4 | **Links in PDF page text**, not only link annotations (read in the sandbox with qpdf). | "links in the page content stream are not extracted" | S |
| C5 | **Detonator: frames and cloaking.** Read forms in every frame, including frames from another site. When the desktop visit shows nothing (403, blank, bot check), retry once with a phone profile and a longer settle; a recognised bot-check page becomes a weak `page.cloaked` signal. | "frames only partly read", cloaking | M |

**Not in H1:** visual brand matching (needs Ollama after the study run), automatic detonation and domain age (D1b), own DKIM verification (needs DNS from this machine), OCR, 7z and RAR (new dependencies), coverage-guided fuzzing (no fuzzer for Python 3.14 on Windows).

### B1 measured (second look at the test halves, logged here)

Rules were changed by looking at D1's dev half and E1's train split only. With the list pinned to E1's Tranco copy (2026-11-10, top 100,000):

- **Real phishing caught:** D1 test half (URL + page, alive pages) OpenPhish 42.7% to 41.6% (one page lost), PhishTank 20.7% unchanged; E1 test PhishTank 3.2% (2 lost of 14,075), PhiUSIIL 2.2% (1 lost of 30,090).
- **Legitimate sets not drawn from Tranco:** PhiUSIIL legitimate test 27 to 20 flagged of 40,685; your browsing 0 of 33 before and after; D1 brand home pages 0 of 51 before and after.
- **Legitimate sets drawn from Tranco (circular, by construction):** D1 test Tranco pages 5 to 0 of 93, Tranco sign-in pages 2 to 1 of 41; E1 test Tranco 146 to 0. The acceptance target "legitimate pages 1% or less" is met on the D1 test half (1 of 185) **only on these circular sets**; the honest reading is that look-alike alarms on popular sites are gone and the long tail is unchanged.
- **Still flagged on D1 dev:** two legitimate pages, by page rules (`page.brand_credential`, `page.form_offsite`). Not tuned: about half of PhishTank's phishing sits on popular hosting platforms, so page rules do not use the list.
