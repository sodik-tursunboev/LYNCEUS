# M0: Foundation

**Goal:** a solid base before any detection logic exists: repo, contracts, database, a labelled seed corpus and an eval harness that runs end to end.
**Rule:** no real detection rules in this milestone. Stub engine only. Tests and eval come first.

This file is the M0 plan. Review it, flag problems, then proceed on approval.

## Tasks

### Repo
- [ ] Init the repo with the layout in `CLAUDE.md`, plus `.gitignore`, `.env.example` and a `README.md` stub.
- [ ] Save the original spec unchanged as `docs/SPEC.md`.
- [ ] Pre-commit hooks: lint and secret scanning.
- [ ] `docs/DECISIONS.md` as an ADR log. ADR-001: modular monolith and trimmed layout (deviates from SPEC §14). ADR-002: Redis deferred (SPEC §4).
- [ ] Pick a Windows-friendly task runner (`up`, `test`, `eval`, `lint`, `migrate`) and record it as an ADR.

### Core skeleton
- [ ] FastAPI app with `/health`, env-based config, structured logging with secret redaction (tested).

### Database
- [ ] PostgreSQL in Docker Compose, Alembic migrations, UUID primary keys.
- [ ] Initial tables: events, artifacts, extracted_urls, domains, provider_results, detections, verdicts, evidence, audit_logs. Sensitive evidence stored apart from metadata. Indexes on lookup columns.
- [ ] Test: migrations apply cleanly to an empty database.

### Contracts
- [ ] pydantic models: Event, Artifact, Signal, Evidence, ProviderResult, Verdict, plus enums for verdict state, confidence and response action. Export JSON schemas.
- [ ] Tests: UNKNOWN never maps to BENIGN, ERROR is its own state, required verdict fields are enforced.

### Corpus and eval
- [ ] `corpus/` manifest format: id, label, category, source or provenance, notes.
- [ ] About 30 synthetic URL seeds: benign, lookalike, punycode, shortener, IP-based, encoded redirect, credential-harvest parameters, SSRF test inputs.
- [ ] `eval/` harness: runs the stub engine over the corpus and reports TP/FP/FN, precision, recall, F1 and latency to `docs/eval/`.
- [ ] Scoring rule in DECISIONS.md: positive = SUSPICIOUS or MALICIOUS; UNKNOWN is reported as an abstain rate, never counted as BENIGN.

### CI
- [ ] On every push: lint, type check, pytest, eval smoke run.

### Threat model and open decisions
- [ ] `docs/THREAT_MODEL.md` v0: assets, trust boundaries, attacker types. Top threats: hostile documents, SSRF, provider poisoning or outage, local IPC spoofing, evidence leakage.
- [ ] Draft three ADRs with options, a proposal and status "needs human sign-off":
  - Parser sandbox: container worker vs restricted Windows process vs VM. Decide before M2.
  - Local IPC: extension ↔ Native Messaging host ↔ agent ↔ core, authenticated, no open unauthenticated ports. Decide before M4.
  - Email transport: Gmail Pub/Sub pull vs push, Graph delta polling vs public webhook. Lean toward pull/polling to stay local-first. Decide before M5.

## Security notes
- No real malicious URLs or samples anywhere. Seeds are synthetic strings; M0 fetches nothing.
- No secrets in git. `.env.example` has placeholders only.

## Done when
- [ ] Tests green on a clean checkout.
- [ ] `eval` runs end to end on the seed corpus and prints metrics. The stub engine will score badly, which is expected; the pipeline is the point.
- [ ] Migrations apply to an empty database.
- [ ] Threat model v0 and the three ADR drafts are committed.
- [ ] Known limitations written and the M1 plan proposed.

## Approved amendments (2026-11-04)

Agreed after review; they override the text above where they differ.

1. **Project location:** `C:\mirage`, own git repo. Local commits only; nothing is pushed anywhere without explicit approval.
2. **Task runner:** stdlib `tasks.py` (`python tasks.py <task>`), no install needed. ADR-003.
3. **Dependencies** (purpose recorded in ADR-004). Runtime: fastapi, uvicorn, pydantic, pydantic-settings, sqlalchemy, alembic, psycopg. Dev: pytest, httpx, ruff, mypy, pre-commit, detect-secrets. Logging uses stdlib `logging` with a redaction filter; no structlog.
4. **Scoring (ADR-005):** the headline recall counts UNKNOWN on a positive sample as a miss. Recall over answered samples is reported alongside it. ERROR is a separate rate, never BENIGN.
5. **SSRF inputs** live in `tests/adversarial/`, not in the scored corpus.
6. **Manifest** gains a `split` field (`dev` | `holdout`) so M1 cannot tune on every sample.
7. **Seed hosts** use only unregisterable names: `.test`, `.invalid`, `.example`, and RFC 5737 addresses (`192.0.2.0/24`, `198.51.100.0/24`, `203.0.113.0/24`).
8. **"UNKNOWN never maps to BENIGN"** is tested through a pure `resolve_state(provider_results)` in contracts, not by enum inspection alone.
9. **Log redaction** covers secret-looking keys and URL query strings and userinfo. URLs are logged as host plus hash, never in full.
10. **Evidence encryption at rest:** M0 only separates evidence payloads into their own table (`ciphertext`, `key_id`). Encryption itself lands in M1, with a fourth draft ADR on key management (DPAPI vs env key).
11. **Initial migration** may be edited in place until M3 (v0.1); nothing is deployed before then.
12. **CI** also runs the secret scan. The eval smoke gate is "harness exits 0 and writes a schema-valid report", not a metric threshold. CI runs on Python 3.12; local development is on 3.14.
13. **Order of work:** contracts, corpus and eval, API and logging, lint and CI, database last (Docker Desktop is not installed and needs separate approval).
14. **`docs/SPEC.md`** is pending: the spec has not been supplied. It will be saved verbatim, never reconstructed.
