# M1: URL engine (PROPOSED, awaiting approval)

**Goal:** a URL goes in, a reproducible, explainable verdict comes out, with evidence, scored by configurable rules, and any URL fetching is SSRF-safe. Quality is measured on the corpus, not demoed.
**Not in M1:** email/file parsing (M2), threat-intel providers (M3), any LLM, any agent or browser integration.

## Modules touched
- `core/urls/` (new): parser and normaliser. Handles userinfo, percent-encoding, IDNA/punycode, mixed-case hosts, trailing dots, IPv4 in decimal/hex/octal/short form, IPv6 and IPv4-mapped forms; registered-domain extraction.
- `rules/url/` (new): the first rule pack, pure functions `artifact -> signals`. Candidates: lookalike/typosquat, homograph/punycode, IP-literal host, brand in subdomain, shortener, encoded or open-redirect parameters, credential-harvest parameters. Each rule: id, category, weight, evidence fields, ATT&CK tag (T1566.002 where it applies), one positive and one negative fixture in `corpus/`, enforced by a test that fails if a rule lacks either.
- `core/risk/` (new): configurable scoring (weights in a config file, not code). One signal alone never yields MALICIOUS.
- `core/urls/resolver.py` (new): SSRF-safe redirect resolver (below).
- `core/detection/`: replace the stub with the real engine behind the same `analyze()` signature.
- `core/api/`: `POST /v1/analyze/url`; logs only host + hash.
- `eval/`: corpus grows; per-category breakdown; report committed under `docs/eval/`.
- `corpus/`: grow from 30 to roughly 150 to 200 synthetic seeds (target to confirm), keeping reserved hosts only and a dev/holdout split. Holdout is for reporting, never for tuning.

## SSRF-safe resolver (security implications)
- Resolve the hostname, then validate every resolved address (loopback, private, link-local, CGNAT, multicast, unspecified, cloud metadata, IPv4-mapped IPv6, and all numeric encodings) before connecting; connect to the validated address, not the name.
- Re-run the whole check on every redirect hop. Cap hops, total time, body size. Allow only `http`/`https` and a port allowlist. Send no cookies or credentials. Never follow into a different scheme.
- Tested only against a fake resolver and a fake HTTP transport using `tests/adversarial/ssrf_inputs.py` plus rebinding and redirect-to-private cases. CI makes no real network calls.

## Dependencies to approve (purpose)
- `httpx` moves from dev to runtime: the fetcher (custom transport so the validated IP is used).
- A public-suffix source for registered-domain extraction: either `tldextract` (bundled snapshot, no network at runtime) or a vendored list. Recommendation: vendored snapshot, no new package, decided at implementation time.
- `cryptography` only if ADR-007 is signed off for M1.

## Acceptance criteria
- Same input and config give the same verdict, score, signals and evidence, in the same order (tested).
- Every rule has a positive and a negative fixture (meta-test).
- `python tasks.py eval` reports TP/FP/FN, precision, recall, F1, abstain and error rates and latency for dev and holdout, committed under `docs/eval/`. No regression against the previous report without a written reason in `docs/DECISIONS.md`.
- The SSRF adversarial suite blocks 100% of probe inputs with a fake network; no test touches the real network.
- A provider-free analysis path never maps an error or timeout to BENIGN (existing contract tests still pass).
- Proposed latency budget for a URL that needs no fetch: p95 under 50 ms (to confirm).
- Lint, types, tests and CI green; known limitations updated.

## Risks
- Tuning rules to 30 to 200 self-written seeds will overfit; mitigated by the holdout split and by stating the corpus size beside every metric.
- Scope creep into fetching page content: out of scope; M1 only follows redirects.
