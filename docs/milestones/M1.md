# M1: URL engine

**Goal:** a local, deterministic URL analysis engine. URL string in, normalized URL + signals + explainable verdict out. Reproducible, measured on a labelled corpus with a holdout split, and no network access by default.
**Rule:** offline signals only. No threat-intel providers (M3), no HTML or email link extraction (M2), no ML.

This file is the M1 plan. Review it, flag problems, then proceed on approval. Propose any new dependency with its purpose before adding it.

**Status (2026-11-04):** approved with amendments (below). Build order is fixed by amendment 1. **Steps 1 (parser, ADR-012) and 2 (corpus) are done**; step 3, rules and scoring, is in progress (ADR-013).

## Tasks

### Parsing and normalization
- [x] Normalize: scheme-less input, whitespace and control characters, backslashes, case, trailing dots, default ports, percent-encoding (flag double-encoding), userinfo (`https://brand.com@evil.example`). *(`core/urls/parse.py`; WHATWG via ada-url; flags report how the input differed.)*
- [x] Hosts: IDN to punycode and back, IPv4 in decimal/hex/octal/mixed forms, IPv6 including IPv4-mapped. Use a bundled Public Suffix List snapshot (no network fetch at runtime). *(Snapshot 2026-11-04, MPL-2.0, hash pinned; `core/urls/psl.py`.)*
- [x] Refang defanged input (`hxxp://`, `[.]`) and extract URLs from plain text. *(`refang`, `core/urls/extract.py`; plain text only, hard caps, linear time.)*
- [ ] Anything unparseable returns UNKNOWN or ERROR with the reason. Never BENIGN. *(The parser returns `ParseFailure(reason)` and never raises on input; turning that into an UNKNOWN verdict happens in the engine step.)*
- Parser conformance: web-platform-tests URL data vendored (commit `c48d587`); 554 of 560 no-base cases match, the 6 differences are deliberate (ADR-012).

### Rule pack v1 (`rules/url/`)
Each rule: id, weight, evidence fields, ATT&CK tag, at least one positive and one negative fixture. Weak features get low weights and only matter in combination.
- [ ] IP-literal host (including obfuscated numeric forms)
- [ ] Userinfo deception (the `@` trick)
- [ ] Punycode and homograph: mixed scripts, confusable with a known brand (UTS #39 skeleton match)
- [ ] Lookalike and combosquat: edit distance, keyboard typos, brand + keyword (`brand-login-secure.example`), brand in subdomain (`brand.com.evil.example`)
- [ ] URL shorteners: signal "destination unknown", never malicious on its own
- [ ] Encoded redirects and open-redirect parameters (`?url=http...`, base64 targets)
- [ ] Credential-harvest patterns (login/verify/update keywords combined with brand terms and path shape)
- [ ] Structure oddities: dangerous schemes (`javascript:`, `data:`), odd ports, excessive length, hyphens or subdomain depth
- [ ] Bundled brand list `rules/url/brands.yaml`: about 100-200 commonly impersonated brands with their legitimate domains and a provenance note
- [ ] Verify ATT&CK IDs against the current ATT&CK version before committing (candidates: T1566.002, T1583.001, T1598.003)

### Scoring and verdict
- [ ] Weights and thresholds live in config, not code. Risk score 0-100, confidence category, ruleset version and engine version in every verdict.
- [ ] Decide and record in DECISIONS.md:
  - BENIGN vs UNKNOWN for rules-only analysis. Proposal: BENIGN with LOW confidence when every configured check completed with no signals; allowlist hit gives BENIGN with HIGH; incomplete checks give UNKNOWN.
  - Whether rule-only verdicts can reach MALICIOUS. Proposal: only with two or more independent high-weight signal categories; otherwise cap at SUSPICIOUS.
- [ ] Determinism test: same input and same versions give identical verdict and evidence (timestamps and ids aside).

### SSRF guard and redirect resolver
- [ ] `safe_fetch` module: http/https only, port policy, resolve DNS then reject non-public addresses (loopback, RFC1918, link-local including 169.254.169.254, CGNAT, multicast, reserved, IPv6 equivalents, IPv4-mapped).
- [ ] Pin the validated IP for the connection (no DNS rebinding gap). Re-validate scheme, host and IP on every redirect hop.
- [ ] Hard caps on hops, total time and response size. No cookies, no auth headers, generic user agent, no body parsing, no JS.
- [ ] **Off by default** (`resolve_redirects=false`). Resolving a link reveals the user's IP and can burn single-use links, which is interaction. Enabling it needs explicit opt-in and the sandbox/egress ADR signed off.
- [ ] Tests use injected fake DNS and a fake transport. No real sockets in CI. Cover: decimal/hex/octal IPs, IPv6 variants, `localhost` names, mixed public and private A records, rebinding (second lookup returns private), redirect to a private IP or non-http scheme, loops, hop cap, oversize and slow responses, ports like 22/6379/9200.

### API and CLI
- [ ] `POST /v1/urls/analyze` returns the full verdict: state, score, confidence, signals (rule id + evidence + ATT&CK tag), normalized URL, recommended response, applied response `none`. Persist event, artifact, verdict and evidence.
- [ ] `mirage analyze-url <url> [--json]`.
- [ ] Contract tests against the exported JSON schemas; OpenAPI generated.

### Corpus and eval
- [x] Grow the URL corpus to 150-200 labelled samples. Record provenance and license for anything non-synthetic. Never fetch corpus URLs. *(253 samples: 150 dev, 49 holdout, 54 reserve; 33 `public_real` benign URL strings, provenance in each entry; `corpus/README.md`.)*
- [x] Include hard negatives: legitimate IDNs, legitimate shorteners, real login pages on real domains, long CDN and tracking URLs, benign lookalikes. *(Also `@` in paths, self-targeting redirects, keyword-bearing pages; Polish and global brands.)*
- [ ] Manifest `split` field: `dev` or `holdout`. Tune rules on dev only. Run holdout at the end and record the numbers. If holdout failures drive a fix, those samples move to dev and a new holdout is drawn. *(Done so far: `dev`/`holdout`/`reserve` split, holdout and reserve hashes pinned by a test, the eval CLI cannot select reserve. Open: running the holdout once and recording it, after the rules.)*
- [ ] Eval report in `docs/eval/` for both splits: TP/FP/FN, precision, recall, F1, abstain rate, per-rule hit counts and precision, p50/p95 latency.

### Docs
- [ ] `docs/DETECTION_ENGINE.md`: rule catalog, scoring model, how to add a rule.
- [ ] `docs/KNOWN_LIMITATIONS.md`: what M1 cannot catch (no reputation, no domain age, no page content, no meta-refresh or JS redirects).

## Security notes
- Corpus URLs are inert strings; nothing is fetched in tests or eval.
- Brand and shortener lists are data files with provenance, not hardcoded in code.
- Any code path that touches the network goes through `safe_fetch`.

## Approved amendments (2026-11-04)

Agreed after review; they override the text above where they differ.

### Decisions
- **D1. Rules-only verdict semantics.** A URL with no signals is **UNKNOWN**, not BENIGN/LOW. BENIGN only on an allowlist match (HIGH). The allowlist never short-circuits other rules: shared-hosting and redirector domains (PSL private section) are never allowlisted, and the userinfo and open-redirect rules still run on allowlisted hosts. Overrides the "BENIGN with LOW confidence" proposal under Scoring. Recorded as an ADR with the scoring work.
- **D2. Persistence.** M1 stores hashes, host, verdict, signals and redacted evidence only. Full URL text waits for ADR-007 sign-off. `Verdict` gains a required `ruleset_version`; a `detection_evidence` table is added (initial migration edited in place, ADR-006).
- **D3. Resolver.** Built last, unwired from the API, enabled by operator config only, never a per-request option. ADR-011 (resolver egress policy) is drafted and needs sign-off. The connector is injected so tests assert it only ever receives the validated IP; one opt-in manual test covers real sockets. httpx with `trust_env=False`; DNS lookup under a deadline; ports 80 and 443 only. The address guard uses `is_global` plus embedded-IPv4 extraction (mapped, NAT64, IPv4-compatible, 6to4) and a table test, since `is_global` alone passes `64:ff9b::7f00:1` and `::127.0.0.1`, and `is_private` alone passes CGNAT.
- **D4. Corpus provenance.** Manifest gains `origin` (`synthetic` | `public_real`). Real hosts only for benign hard negatives, with provenance, license and "public page, no personal tokens". Malicious samples are always synthetic on reserved hosts (lookalikes of real brands on `.test`). No phishing-feed URLs in git.

### Changes requested by the owner
1. **Build order:** parser, then corpus (dev + sealed holdout + reserve, manifest hash pinned), then rules and scoring, then eval, then API/CLI/persistence, then the resolver. One commit per step.
2. **Eval metrics:** UNKNOWN on a malicious sample counts as a miss (FN) for recall; abstain rate is reported separately. On benign samples report the **flag rate**; UNKNOWN counts as not flagged. (ADR-005 gains a flag-rate line.)
3. **Oversize URL:** UNKNOWN with a reason, not 422. HTTP 422 only for malformed requests. The raw request body size is capped separately.
4. **Eval report wording:** it states plainly that synthetic positives measure rule correctness, not the real-world detection rate.
5. **Brand list:** includes Polish targets (InPost, Poczta Polska, PKO BP, mBank, Allegro, OLX, BLIK) next to the global ones. (Format: TOML, see below.)
6. **Verdict** carries both `ruleset_version` and `engine_version`.
7. **PostgreSQL via Docker Desktop.** The owner supplies `docs/SPEC.md`.

### Folded in from review
- **Parser reference is the WHATWG URL Standard**, never `urllib` (it disagrees with browsers on `\`, e.g. `http://evil.example\@good.example/`). `ada-url` is used if the evaluation passes; differential cases are kept as regression fixtures.
- Config and brand list are **TOML** (`tomllib`, stdlib); PyYAML is only a dev dependency. `rules/url/brands.toml` replaces `brands.yaml`.
- Eval: default run is dev only; `--split holdout` is explicit and appends to `docs/eval/holdout_runs.md` (date, ruleset hash, numbers); Wilson 95% intervals beside every rate; per-split report files; the holdout manifest hash is pinned by a test.
- Write about 250 samples; keep about 50 sealed as `reserve` so "draw a new holdout" is possible. Holdout is written before the rules.
- Scoring: noisy-OR with a per-category cap; "independent categories" come from a taxonomy in config; `ruleset_version` = semver + content hash of config and data files; signals sorted by rule id.
- ATT&CK: lookalikes tagged T1566.002; T1583.001 (acquiring domains) is informational only. All IDs are checked against attack.mitre.org when the rules are written.
- Brand list is drafted from general knowledge and every entry is `verified = false` until the owner reviews the legitimate domains.
- CLI: `python -m core.cli analyze-url` (no package or entry point yet; a `mirage` console script waits for packaging in M7).
- API: JSON body only; bind `127.0.0.1`; trusted-host allowlist; no CORS; linear-time regexes with a pathological-input timing test; WHATWG parse failure is UNKNOWN `unparseable`; an internal exception is ERROR; refanged input is flagged in evidence.
- Offline tests: a conftest guard fails any non-loopback connect or DNS lookup (loopback stays open because asyncio on Windows uses a loopback socketpair).

### Dependencies
- `ada-url`: WHATWG parser and IDNA, adopted after evaluation (wheels exist for Windows and Linux on Python 3.12 and 3.14).
- `idna`: approved, but **not added** if `ada-url` covers IDN conversion (ADR records the outcome).
- `httpx`: moves to runtime at the resolver step only.
- Data files with recorded source, date, sha256 and license: the Public Suffix List snapshot (MPL-2.0) and Unicode `confusables.txt`.
- web-platform-tests `urltestdata.json` (BSD-3): approved and vendored as a subset in `tests/data/wpt/`, with source commit and license.

### Proposed after reading SPEC.md (not yet approved; owner to confirm)
- **P1. API authentication and rate limiting (SPEC §9: "strict API authentication", "rate limiting").** The analysis endpoint requires `Authorization: Bearer <token>`; the token comes from `MIRAGE_API_TOKEN` (compared in constant time, never logged, endpoint refuses to serve without one). A small in-process rate limit sits in front of it. `/health` stays open and returns nothing but `ok`. This also closes the "any local process or rebinding page can call the API" gap from D3. Added to the API/CLI step.
- **P2. Risk score is `null` for UNKNOWN and ERROR** although SPEC §7 lists a risk score on every verdict (ADR-006). Keeping it is my recommendation; say so if you want a number there.
- **P3. Two different "allowlists".** D1's allowlist is bundled data (the legitimate domains in `brands.toml`) used by the rules. The user-managed `allowlist` and `blocklist` tables in SPEC §13 are a separate feature and arrive with the response engine and console (M6).
- **P4. Spec scope notes.** SPEC §6 also lists "redirect chains" and "domain reputation" under URL detection; with the resolver off and no providers, M1 reports neither (they are documented as limitations, not silently absent).
