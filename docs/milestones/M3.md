# M3: Threat intelligence, correlation, export (v0.1)

**Status (2026-11-05): built, tested and recorded; pending your review (tagged `v0.1`).** Approved by the owner with the recommended answer to each of D1 to D8. See the progress table, the deviations and the verification at the end.

**Goal (CLAUDE.md M3, SPEC §5 and §15 phase 3):** add independent intelligence sources behind one interface, combine them with the local rules by correlation, and export verdicts as JSON lines. **Done when any provider being down still returns a verdict.** This is v0.1: the initial migration freezes at the end of M3 (ADR-006).
**Not in M3:** following or fetching any URL (the resolver stays off, ADR-011), any LLM (after M3), live mailboxes (M5), the agent and extension (M4), pushing to any external system.

## The problem that shapes everything: what leaves the machine

CLAUDE.md rule 4 and SPEC §5: private URLs, tokens and mail content never leave the machine without explicit authorization. Providers fall into two kinds, and the plan treats them differently:

| Kind | Examples | What is sent | Default |
|---|---|---|---|
| **List feeds** (download a list, match locally) | PhishTank, OpenPhish, URLhaus, Safe Browsing v5 local lists | Nothing about your URLs. (Safe Browsing sends a 4-byte hash prefix only after a local match.) | On, once the operator has put a key/enabled it |
| **Query providers** (ask about one subject) | VirusTotal, RDAP, urlscan, Web Risk Lookup | A host name at least; a full URL for some | **Off.** Each is enabled one by one in server config, which is the recorded authorization |

Rules for query providers, enforced in one place (`core/intel/egress.py`) and tested by capturing the real request: **only the host (registered domain where the API allows) is sent, never a path, query, fragment, userinfo or token; never a host that is not a public name (single label, `.local`, private or loopback address, no public suffix); never from an email's links unless `MIRAGE_INTEL_EMAIL_LINKS=true`.** There is no per-request switch: a caller of the API cannot ask for a provider. Every enabled query provider is written to the audit log at start-up with what it sends.

## Design

- **`core/intel/`** (new): `Provider` protocol (`async lookup(subject) -> ProviderResult`, plus a declared `sends: nothing | host`); orchestrator (concurrent, per-provider timeout, overall deadline); circuit breaker (closed, open, half-open; open gives `UNAVAILABLE` with no call); token-bucket limiter per provider set to the verified limits; cache (positive results with a TTL, a failure is **never** cached as an answer, only a short back-off); provenance on every result (feed, version, date).
- **Feeds** (`core/intel/feeds.py`, `python -m core.intel sync`): conditional download (ETag / HEAD), size and entry caps, atomic replace, previous copy kept on a bad download; entries stored as `sha256(normalized URL)` using the M1 parser, so a lookup is an exact local match on `ParsedUrl.url_sha256`, plus a host index for a weaker "host is listed" signal. A feed older than twice its interval reports `UNAVAILABLE` (stale), never "clean".
- **Correlation** (`core/risk/correlate.py`, `rules/intel/scoring.toml`): provider results become signals in `intel.<provider>` categories and go through the same noisy-OR scoring and the two-category rule. `resolve_state` (the M0 placeholder) is replaced. RDAP adds `intel.domain_age` (weights by age bands, configurable). Provider failures are listed in `provider_results` and in the explanation ("2 of 5 providers unavailable"); they never lower or raise the score.
- **Offline stays offline:** `analyze_url` and `analyze_message` remain pure and network-free. A new async wrapper composes local verdict, then intel under a deadline (default 2 s), then correlation. A provider that misses the deadline is recorded `TIMEOUT`, and its late answer still warms the cache. The extension (M4) will never wait on a provider.
- **Hostile responses:** every provider reply is untrusted: size cap, depth cap, strict models (unknown fields ignored but required ones validated), strings truncated; nothing from a reply is put into an explanation unescaped.
- **Persistence:** `provider_results` (exists) gets rows; new `feed_entries`, `feed_state`, `intel_cache` tables go **into the initial migration, which is edited one last time** and then frozen (forward-only from v0.1).
- **API/CLI:** `/v1/urls/analyze` response gains real `provider_results`; `GET /v1/intel/health` (per provider: state, last success, breaker, feed age; no keys); `python -m core.intel sync|status|lookup <host>`; `python -m core.export --since ... [--out file]`.
- **Dependencies:** none new expected (httpx is already approved and listed; bz2, asyncio, sqlite/Postgres are in place). Safe Browsing v5 may need none either.

## Security implications

Egress is the new attack surface and the new privacy risk. Controls: the egress gate (host only, public names only, tested on captured requests); everything off by default; allowlist of destination hosts per provider (fixed names, https only, public IPs only, redirects not followed); the RDAP server comes from the IANA bootstrap file, so it is validated like attacker input; key scrubbing; response caps; no provider can cause a URL to be fetched by us. A malicious feed entry or provider reply must not be able to inject into logs, SQL, or the explanation.

## Acceptance criteria

1. With every provider failing in turn and all at once (timeout, 429, 500, garbage JSON, oversized body, connection refused), the verdict equals the local verdict plus the failure records; no failure produces BENIGN.
2. The deadline bounds added latency (slow fake provider, fake clock); late answers warm the cache.
3. Breaker opens after repeated failures, calls stop, half-open recovers (fake clock); the limiter never exceeds a provider's limit; 429 backs off.
4. Egress tests capture every outgoing request: no path, query, token, userinfo or non-public host ever appears; default config sends nothing; email links send nothing by default.
5. Feed sync handles ETag, partial, corrupt, oversize and stale downloads without losing the last good copy.
6. Keys never appear in logs, exceptions, the database or the repo (a test plants a key and scans all three).
7. Correlation: two agreeing providers give MALICIOUS, one gives SUSPICIOUS, none gives the local verdict; golden tests for each case.
8. JSONL export is deterministic, schema-documented, contains no URL text, and re-imports cleanly in a test.
9. Determinism, network-blocked tests (providers use `httpx.MockTransport`), PostgreSQL tests, clean-checkout run, lint; docs, limitations and the v0.1 tag.
10. **Not claimed:** that any adapter works against the live service, or how much the providers add in the real world, until you run the manual live check with your keys. If D8 is approved, that check also reports the rules' recall on real phishing URLs.

## Risks

- Terms: three of the free tiers (VirusTotal, OpenPhish, URLhaus) forbid more than personal use; a later decision to distribute changes the provider set and costs money.
- Feeds can vanish or change (OpenPhish may end the feed; PhishTank mentions a rewrite).
- Without keys I cannot verify any adapter live; wrong assumptions about response shapes are likely in the first run.
- Rate limits for PhishTank, URLhaus and RDAP are unpublished; the limiter starts conservative and is tuned from observed headers.
- Provider verdicts are not ground truth (urlscan's own FAQ warns against unattended blocking on them); correlation keeps them as evidence, not as the decision.

## Deviations from the approved plan (so far)

- **Feeds are stored as files, not tables.** The plan said `feed_entries` and `feed_state` tables. Files (sorted hash lists plus a small metadata file, replaced atomically) keep analysis working with no database, as it does today, and need no schema change.
- **The answer cache is in memory.** The plan said an `intel_cache` table. A restart forgets cached answers and the day's request count (a documented limitation); nothing in the database changes, so the initial migration is frozen as it stands.
- **The egress gate also refuses IP addresses** (public ones included) and any name outside the Public Suffix List, which is stricter than the plan's wording.
- **List entries are matched on a hash of the normalized URL without its fragment** (a server never receives a fragment; feeds carry or lack it). Entries without an explicit `http://` or `https://` are dropped, because the URL parser would guess a scheme for a bare word.
- **Bug found by a test while writing step 2:** httpx logs every request URL at INFO, which would have written a PhishTank or URLhaus key (they sit in the download URL) into the logs. The httpx and httpcore loggers are now held at WARNING.
- **Network code is confined to one file.** `httpx` is imported only in `core/intel/http.py` (plus the unwired `safe_fetch.py`); the "nothing else opens a socket" test now names both, and a second test checks that no analysis engine imports `core.intel`.
- **The email ruleset was not touched.** Intelligence signals on message links arrive in categories `link.intel.<provider>` with no explicit cap in `rules/email/scoring.toml` (the default of 1.0 applies, and the within-provider cap is already in `rules/intel/scoring.toml`), so the message ruleset hash that the holdout run used is unchanged.
- **RDAP servers named by the bootstrap file are checked by name only** (https, a public name under a known suffix, no IP literal, no credentials, port 443). A name that resolves to a private address is not blocked: doing that needs the connect-by-validated-IP machinery in `safe_fetch`, which is unsigned (ADR-011) and which a test keeps unimported. The bootstrap file arrives over HTTPS from IANA; someone able to alter it can do worse than this.
- **Request counts for VirusTotal reset on restart** (in-memory limiter), so a restart can spend part of the 500/day twice; a daily-quota 429 pauses until the UTC reset.
