## Acceptance criteria

1. `python -m eval.perf` runs from a clean checkout and `docs/PERFORMANCE.md` states the numbers and the machine.
2. The randomised tests pass with a fixed seed and fail when a safeguard is removed (mutation-checked).
3. `deploy/install.ps1` takes a clean clone to a running install (agent answering through its pipe, core healthy, console served), `-Upgrade` keeps the data folder, `uninstall.ps1` removes what install added; all verified by running them.
4. The documents describe only what the code does (checked against the code, not remembered).
5. Not claimed: that CI passes, a signed or MSI installer, a native console, Chrome, anything needing the items above.

## Results (2026-11-05)

**Status: the parts that need nothing from you are built and verified; the parts in "Needs you" are not started.**

| Acceptance criterion | Evidence |
|---|---|
| 1. Measured | `python -m eval.perf` and `docs/PERFORMANCE.md`: one URL about 0.8 ms in process; a message 0.3 to 0.7 s and a file 0.19 to 0.46 s through the sandbox (a fresh sandbox process per item dominates); the API sustained about 280 requests a second with 8 clients and the rate limiter lifted (the default limit is 120 a minute); bundle sizes. Machine stated |
| 2. Attacked | seeded randomised tests: 600 random requests to every response route (ids, headers, bodies, query strings) never return an unhandled error or leave the database in a forbidden state; random events on real actions never reach a state the machine forbids; 300 console-path traversal attempts serve nothing outside the folder; .NET: 30,000 random or mutated protocol messages, 5,000 random frame streams, 300 garbage stdin streams into the host, 25 rounds of garbage into the pipe server, 5,000 hostile answers into the core client; the pipe server still answers the next valid request. **They found two real defects, both fixed:** `Protocol.TryParse` threw (instead of refusing) when a JSON string held invalid UTF-8, which closed the connection instead of answering; and an unknown actor name could reach the audit log from a direct service call (now recorded as the user). Both fail the tests if reverted |
| 3. Deploy | `deploy\install.ps1` run for real from this checkout into a temporary folder with its own data folder and port: built the agent, extension and console, installed, wrote the config, started the agent, and the core answered and served the console in 9 seconds; run again as an upgrade: the agent was stopped, replaced and restarted (new process), the token, spool and config were kept; `deploy\uninstall.ps1` removed the install and kept the data; `-RemoveData` removed it too; the author''s own running agent was untouched throughout. Registry registration is covered by the existing installer tests (a temporary registry root), not by this script test (`-NoRegister`). A from-scratch clone run is recorded below |
